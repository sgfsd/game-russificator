# Как устроен русификатор

## Общая схема

```
ui/ (окно: pywebview + HTML)   cli.py (командная строка)   play.py (ярлык «Играть на русском»)
ui/games.py + library.py («Мои игры»)   overlay/ (живой перевод поверх экрана, отдельный процесс)
core/package.py + installer/ (архив «для друзей» и его установщик)
                  \                  |                     /
                   core/pipeline.py: определить → подготовить → извлечь → перевести → встроить → шрифты
                  /                  |                     \
engines/<движок>/plugin.py   translation/ (4 способа перевода)   fonts/ (PT Sans, чтение cmap)
                  \                  |
                   core/universal.py: Entry — строка игры (текст, тип, говорящий, соседи, адрес)
                   core/backup.py:    всё, что меняется в игре, записывается в russificator_backup/manifest.json
```

Плагин движка знает только, как найти текст и как вернуть перевод на место.
Слой перевода не знает о движках. Всё, что пишется в папку игры, идёт через
`GameBackup`: оригинал сохраняется до первой правки, новые файлы запоминаются.
Откат (`core/restore.py`) возвращает ровно это. Повторная русификация сначала
откатывает прошлую, а готовые переводы берёт из прошлого проекта
(`RussificatorData/projects/`).

## Перевод (`translation/`)

- `service.py`: общий конвейер для всех способов. Пропускает то, что не надо
  переводить, убирает повторы, берёт готовое из памяти переводов (SQLite,
  `cache/translations.db`), отправляет строки пачками с контекстом, параллельно
  (облако), проверяет результат. То, что не перевелось пачкой, «спасается»:
  по одной строке, затем по кускам между разметкой (`translate_by_segments` —
  структура строки не может сломаться), затем запасным машинным переводчиком,
  если он скачан. Английской строка остаётся, только если не справился никто.
- `markup.py`: теги, плейсхолдеры, коды RPG Maker/Ren'Py/Unity. Перевод обязан
  сохранить весь набор вставок, иначе он отбрасывается и делается заново через
  маскирование (`@0`, `@1`…).
- `machine.py` (способ 1): модель Argos Translate en→ru, запускается напрямую
  через CTranslate2 + SentencePiece, построчно, с глоссарием фраз интерфейса.
- `local_llm.py` (способ 2): llama.cpp (сборка Vulkan) как локальный сервер,
  модели Gemma 4 GGUF, пресет подбирается по ОЗУ/видеопамяти.
- `cloud.py` (способ 3): любой OpenAI-совместимый API; список моделей берётся
  у провайдера, `recommend()` ставит подходящие для перевода первыми.
- `llm.py`, `prompt.py`: общий клиент и промпт для нейросетей (JSON-ответ,
  короткие id, соседние реплики как контекст, деление пачки при сбое).
- `live_server.py`: HTTP-сервер для XUnity (Unity) — перевод на лету.

## Unity (`engines/unity/`)

Перевод работает в самой игре: BepInEx + XUnity.AutoTranslator
(`xunity.py`). Русификатор заранее готовит словарь
`BepInEx/Translation/ru/Text/_Russificator.txt`, а строки, которых в нём нет,
XUnity присылает на `live_server.py` (порт 47631).

Откуда берётся текст для словаря (`extract.py`, `text_assets.py`):
- компоненты текста сцен и префабов (UGUI Text, TextMeshPro, NGUI, TextMesh):
  typetree скриптов строится из сборок игры (TypeTreeGenerator), для IL2CPP —
  из `GameAssembly.dll` + `global-metadata.dat`;
- строковые поля скриптов (фразы, короткие названия в полях вроде `productName`);
- скрипты, чей typetree не сходится с данными, читаются по сырым байтам
  (строка Unity = int32 длина + UTF-8 + выравнивание 4);
- литералы кода (`#US` .NET-сборок или строки `global-metadata.dat`);
- текстовые ассеты: JSON, CSV/TSV (колонка английского), XML, Ink (`^текст`),
  Yarn («Имя: реплика»), простой текст — только то, что похоже на фразы;
- страницы встроенного браузера ZFBrowser (`zfbrowser.py`, пакет
  `Resources/browser_assets`, формат `zfbRes_v1`): переводятся прямо в
  пакете, только видимый текст, русские буквы — HTML-сущностями.

Плагин русификатора в игре (`resources/unity/RussificatorUnity.cs` →
`Russificator.Unity.dll`, BepInEx 5, Mono; все типы Unity/TMP — через отражение,
поэтому одна сборка работает на Unity 5–6):
- при старте игры читает `BepInEx/config/Russificator.cfg` и, если порт живого
  перевода свободен, запускает программу в режиме `--serve <игра> --pid <процесс>`
  и ждёт, пока она откроет порт; программа закрывается вместе с игрой. Живой
  перевод поэтому работает при любом способе запуска игры;
- перехватывает `TMP_Text.SetText(string)` (XUnity его не видит) и направляет
  через свойство `text`;
- после перевода проверяет элемент TextMeshPro/UGUI: русский текст вылезает за
  рамку или рвёт слово (перенос посреди слова виден в `textInfo`), а английский
  помещался — включает автоподбор размера от исходного вниз до 60%.

Надёжность живого перевода. XUnity отключает перевод после 5 ошибок подряд,
поэтому сервер открывает порт за доли секунды (переводчик готовится в фоне), а
запросы ждут готовности модели. Негодный перевод переводится по кускам, а если
и так нельзя — возвращается оригиналом, а не ошибкой. Для IL2CPP (плагина нет)
ярлык «Играть на русском» (`core/launcher.py` → `play.py`) поднимает сервер без
окна, запускает игру и закрывается вместе с ней (ждёт и перезапуск через Steam).

IMGUI (`GUI.Label`…) XUnity перехватывает, только если `il_scan.py` нашёл такие
вызовы в коде игры.

Текст, печатающийся по буквам: `GeneratePartialTranslations=True`, если
словарь небольшой (бюджет по сумме квадратов длин строк). Тогда XUnity
заранее строит перевод каждого начала строки. Если код игры дописывает буквы к
тексту, прочитанному из компонента (`label.text += c`), включается ещё
`TextGetterCompatibilityMode`: коду игры возвращается оригинал. Нужен ли он,
решает `il_scan.py`: он разбирает IL-код сборок игры и ищет шаблоны
«get_text → Concat → set_text» (нужен) и «text.Length → maxVisibleCharacters»
(вреден: игра обрезала бы более длинный русский текст).

Подписи, к которым код приклеивает текст (`"Pro Tip: " + tip`), берутся из
литералов кода и записываются в словарь как splitter-regex XUnity
(`sr:"^Pro Tip: ([\S\s]+)$"=Совет: $1`): подпись переводится один раз, а
вставка — по словарю или живым переводом.

TextMeshPro: XUnity перехватывает свойство `text` и `SetText(string, bool)`, но
не `SetText(string)`, которым пользуются игры на старом TMP. Плагин
`resources/unity/RussificatorTmpFix.dll` (исходник рядом, `.cs`) перенаправляет
`SetText(string)` в свойство `text`. Ставится для Mono-игр с BepInEx 5.

Русский текст шире английского: для переведённых компонентов пишется
`_Russificator.resizer.txt` с `AutoResize(true, 60%, исходный размер)` по полному
пути объекта в сцене (так XUnity ищет правила). Шрифт не становится крупнее
исходного и уменьшается, только если текст не помещается.

Шрифты (`tmp_cyrillic.py`): для каждого шрифта TextMeshPro (v1 и v2) без
кириллицы русские буквы рисуются в свободное место атласа (атлас растёт при
нехватке) как SDF с параметрами шрифта (Padding, GradientScale). Высота
заглавных и ширина подгоняются под оригинал. Растровые шрифты Unity (`Font`
с текстурой) дополняются так же. После записи файл перечитывается и
проверяется.

## Ren'Py (`engines/renpy/`)

- `archive.py`: RPA-2.0/3.0/3.2, индекс читается безопасным unpickler'ом;
- `rpyc.py`: скомпилированные скрипты читаются без выполнения кода
  (заглушки классов Ren'Py), `rpy_parse.py`: исходники, по правилам лексера Ren'Py;
- кроме реплик, меню и `_()` извлекаются аргументы `renpy.notify`, `renpy.input`,
  `renpy.say`, `Text`, `Confirm`, `Notify` и свойства экранов (`tooltip`…);
- встраивание: `game/russificator_tl.json` + `zz_russificator.rpy`
  (`config.say_menu_text_filter`, `config.replace_text`), шрифты без
  кириллицы подменяются PT Sans через `config.font_replacement_map`;
- реплика, которая не помещается в окно диалога (высота меряется самим Ren'Py:
  `Text(...).size()`), получает `{size=-N}` ровно на нужную величину — только в
  режиме ADV и только если английский оригинал помещался.

## RPG Maker (`engines/rpgmaker/`)

- `layout.py`: перенос по ширине в пикселях (метрики PT Sans из `fonts/metrics.py`)
  с размерами окон каждой версии, поправкой на разрешение (MZ — `System.json`, MV —
  параметры плагинов) и шириной управляющих кодов;
- MV/MZ (`mv_mz.py`): блоки сообщений (101 + 401) переводятся целиком и заново
  переносятся по ширине окна (с портретом и без), выборы, прокрутка, база
  данных, `System.json`, названия карт, `$gameMessage.add` в скриптах (355/655),
  аргументы команд плагинов MZ (357) и параметры `js/plugins.js`
  (`plugin_text.py`: только «текстовые» имена параметров, JSON внутри строк
  раскрывается и собирается обратно). Плагин `resources/rpgmaker/Russificator.js`
  (подключается последним) переносит слово, которое не влезло в окно
  сообщения/прокрутки/справки, и уменьшает шрифт описаний и строк боя; проверен на
  моделях окон MV и MZ (`tests/js`). Шрифт: MV — `@font-face` с `unicode-range`
  для кириллицы, MZ — `mainFontFilename`;
- XP/VX/VX Ace (`old_marshal.py`, `ruby_marshal.py`): точный читатель/писатель
  Ruby Marshal 4.8, архивы RGSSAD v1/v3 (`rgssad.py`) распаковываются в `Data/`.
  Надписи в скриптах (`rgss_scripts.py`): константы `Vocab`, «текстовые»
  константы, `add_command`, `draw_text`, меню XP — замена литерала по месту с
  экранированием Ruby. Описания VX Ace разбиваются на две строки (или получают
  `\}` — меньший шрифт). Шрифт: `Fonts/` + скрипт перед `Main`.

## Данные программы (`paths.py`)

Всё лежит в `RussificatorData` рядом с exe (из исходников — `userdata/`):
`models/` (машинный переводчик, GGUF), `tools/` (llama.cpp, BepInEx, XUnity),
`cache/` (память переводов), `projects/`, `logs/` (`russificator.log`, `play.log`),
`settings.json`. Папку можно перенести в настройках.

## Русификатор «для друзей» (`core/package.py`, `installer/`)

Архив `<Игра> — русификатор.zip` = `Установить.exe` + `Прочти.txt` + лицензии +
`russificator-data/` (`package.json`, `translations.json`, `files/`, `patches/`).
Как ставить, решает движок (`EnginePlugin.export_plan` → `ExportPlan`):

- `files` (Ren'Py, Unity): копируются созданные русификатором файлы (из манифеста бэкапа,
  без кэшей BepInEx, логов и ярлыков); изменённые файлы игры — бинарными патчами
  `core/delta.py` (жадное совпадение блоков через `mmap.find`, проверка SHA-1 до и после);
  конфиги «для друзей» подменяются (Unity: без сервера программы, с надписью о программе);
- `reinject` (RPG Maker): у друга текст извлекается из его копии игры тем же кодом, перевод
  подставляется по адресу и тексту строки (`apply_translations`) и внедряется заново — так
  подходит к любой версии игры.

Установщик (`installer/app.py`, Tk, `installer.spec`) собирается без UnityPy/numpy: движки
Ren'Py и RPG Maker — чистый Python (XOR архивов RGSSAD без numpy — длинной арифметикой).
Всё пишется через `GameBackup`, поэтому удаляет и установщик, и программа («Откатить»).

`GameBackup.snapshot()` запоминает размер и время изменения файлов после русификации:
«Мои игры» видят, что обновление игры затёрло перевод, а откат не возвращает старые
файлы поверх обновлённых (`forget_updated`).

## Мои игры (`library.py`, `ui/games.py`)

Источники: Steam (`libraryfolders.vdf`, `appmanifest_*.acf`), GOG и Ubisoft (реестр), Epic
(манифесты `.item`), itch.io (папка приложений и `butler.db`), Game Pass (`XboxGames` на
дисках), список установленных программ Windows (только папки с игровым движком), свои папки
и проекты программы. Движок определяется быстро по характерным файлам. Список кэшируется в
`cache/library.json` и обновляется в фоне.

## Unity: шаблоны из кода (`xunity.template_rules`, `il_scan.concat_templates`)

Строки с плейсхолдерами `String.Format` («You have {0} coins») превращаются в правила-регулярки
XUnity: числа переносятся как есть (`r:`), текстовые вставки переводятся отдельно (`sr:`).
Склейки строк в Mono-коде находятся упрощённым вычислением стека IL (`String.Concat`, в том
числе с массивом) и становятся шаблонами «Day {0} of {1}». Ключи правил в файле XUnity
экранируются целиком (`xunity.encode`).

Плагин Unity — один исходник `RussificatorUnity.cs`: Mono (BepInEx 5) и с символом `IL2CPP`
(BepInEx 6, Il2CppInterop: объекты по указателю, текст через свойства, свой компонент для
Update/OnGUI). Сборка — `tools/build_unity_plugins.py`.

## Живой перевод (`overlay/`)

Процесс `Russificator.exe --overlay` (трей, автозапуск через `HKCU\...\Run`):

1. `detect.Decider` — игра ли окно переднего плана (списки, «Мои игры», GameConfigStore,
   файлы движка рядом с exe — `engine_near`, полный экран; браузеры/мессенджеры/система — никогда);
2. `win32.capture_window` — кадр с самого окна игры (`PrintWindow` c `PW_RENDERFULLCONTENT`,
   клиентская область): наших плашек и чужих окон в нём нет. Если окно так не снимается —
   `win32.capture` (BitBlt области экрана), а место плашек в кадре закрашивается и блоки под ними
   не пропадают (`Tracker.update(covered=…)`). `WDA_EXCLUDEFROMCAPTURE` для per-pixel alpha окна в
   Windows 10 не работает (ошибка 8), поэтому на него служба не полагается;
3. `ocr` — Windows.Media.Ocr: через pythonnet в процессе, запасной путь — PowerShell 5.1 со
   скриптом `resources/overlay/ocr.ps1`. Второе, русское распознавание (`create_verifier`)
   проверяет строки-кандидаты: английское читает русский текст как «HaqaTb», русское — как
   «Начать» (`text.looks_russian` считает только кириллицу без латинских двойников, иначе «EXIT»,
   прочитанное как «ЕХIТ», сошло бы за русское). Без русского распознавания —
   `text.misread_cyrillic` по приметам (цифры и значки в словах, «Bbl», смена регистра);
4. `text` — иностранные строки → абзацы; отсеиваются заголовок окна, заставки движков
   (`is_brand`), мусор (`junk_tokens`, `gibberish`) и слова названия игры (логотип); `Tracker`
   ждёт, пока текст перестанет печататься, и отличает шум распознавания; `TranslationCache` —
   нечёткий кэш сессии;
5. глубокий проход (`vision.variants` + `text.merge_deep`) на замершем кадре и раз в
   `DEEP_INTERVAL` с (не больше `DEEP_SHARE` времени): кадр распознаётся в вариантах (серый с
   растянутым контрастом, насыщенность, синий и красный каналы, увеличение x2 для мелких окон),
   строка принимается по голосам двух вариантов; крупные надписи, прочитанные лишь частично,
   отбрасываются. Найденные блоки держатся (`hold_until`), пока быстрый проход их не видит; при
   смене сцены (`vision.changed_share`) пропавшее убирается сразу;
6. перед переводом новый блок перечитывается крупнее (x2–x3, только его область — `_refine`), а
   текст правится словарём (`words.Words.fix`: английские слова из sentencepiece-модели Argos,
   типичные замены букв и «взвешенное» расстояние — t↔l, s↔g, rn↔m стоят дёшево);
7. перевод в фоновом потоке пачками (общая память переводов); перевод без русских букв или
   совпавший с оригиналом не показывается (`SKIP`);
8. `render` — плашки PIL (шрифт подгоняется под рамку, плашка закрывает весь абзац) →
   `win32.Gui`: многослойное окно поверх игры, прозрачное для мыши.

Окно программы управляет процессом по HTTP на 127.0.0.1:47632 (`/status`, `/toggle`, `/reload`…).

Горячие клавиши (`RegisterHotKey`) регистрируются только пока на экране игра, поэтому в других
программах Alt+… не перехватываются; в играх, русифицированных файлами (есть `russificator_backup`
или XUnity), Alt+T остаётся игре. Обычное окно, не похожее на игру, запоминается как «кандидат» —
его можно включить из меню трея или вкладки. Если у полноэкранной игры с самого начала только
чёрные кадры (эксклюзивный полноэкранный режим), служба подсказывает переключить «окно без рамки».
Кадр больше `OcrEngine.MaxImageDimension` уменьшается перед распознаванием.

Настройки пишут два процесса (окно и трей): `settings.save` сливает изменения — ключи, которые
этот процесс не менял с момента чтения, берутся из файла.
