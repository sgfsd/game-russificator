# Как устроен русификатор

## Общая схема

```
ui/ (окно: pywebview + HTML)   cli.py (командная строка)   play.py (ярлык «Играть на русском»)
ui/games.py + library.py («Мои игры»)   overlay/ (живой перевод поверх экрана, отдельный процесс)
core/package.py + installer/ (архив «для друзей» и его установщик)
                  \                  |                     /
                   core/pipeline.py: определить → подготовить → извлечь → перевести → встроить → шрифты
                  /                  |                     \
engines/<движок>/plugin.py   translation/ (4 способа перевода)   fonts/ (PT Sans, чтение cmap)
                  \                  |
                   core/universal.py: Entry — строка игры (текст, тип, говорящий, соседи, адрес)
                   core/backup.py:    всё, что меняется в игре, записывается в russificator_backup/manifest.json
```

Плагин движка знает только, как найти текст и как вернуть перевод на место.
Слой перевода не знает о движках. Всё, что пишется в папку игры, идёт через
`GameBackup`: оригинал сохраняется до первой правки, новые файлы запоминаются.
Откат (`core/restore.py`) возвращает ровно это. Повторная русификация сначала
откатывает прошлую, а готовые переводы берёт из прошлого проекта
(`RussificatorData/projects/`).

## Перевод (`translation/`)

- `service.py`: общий конвейер для всех способов. Пропускает то, что не надо
  переводить, убирает повторы, берёт готовое из памяти переводов (SQLite,
  `cache/translations.db`), отправляет строки пачками с контекстом, параллельно
  (облако), проверяет результат. То, что не перевелось пачкой, «спасается»:
  по одной строке, затем по кускам между разметкой (`translate_by_segments` —
  структура строки не может сломаться), затем запасным машинным переводчиком,
  если он скачан. Английской строка остаётся, только если не справился никто.
- `markup.py`: теги, плейсхолдеры, коды RPG Maker/Ren'Py/Unity. Перевод обязан
  сохранить весь набор вставок, иначе он отбрасывается и делается заново через
  маскирование (`@0`, `@1`…).
- `machine.py` (способ 1): модель OPUS-MT tc-big en→ru (Helsinki-NLP; готовая сборка
  CTranslate2 с HuggingFace, закреплённая версия, а без неё — официальный архив, конвертируемый
  `OpusMTConverter`), запасная — Argos Translate en→ru; запускается напрямую через CTranslate2 +
  SentencePiece, по предложениям, с глоссарием фраз интерфейса (и в рамке из знаков: «-NEW-»).
  Фраза, разбитая игрой на строки посреди предложения («insert↵coin» — следующая строка
  со строчной буквы), переводится целиком и раскладывается на столько же строк
  (`join_soft_wraps`/`rewrap`). Если в переводе остались английские слова оригинала (модель
  принимает Заглавный Регистр и КАПС за имена: «Sallow Пещера», «LEVEL 7»), строка
  переводится ещё раз в обычном регистре — берётся вариант, где английского меньше.
  Правила перевода версионируются (`rules_version`/`redo`):
  строки прошлых проектов, которые новые правила переводят иначе, переводятся заново, а
  память переводов для них — в своём разделе (`memory_ns`).
- `filters.py`: что не переводится — служебные строки, сетка букв («ABCD↵EFGH»), а у
  короткого слова «перевод»-транслитерация («DAP» → «ДАП», «2ND» → «НД») заменяется
  оригиналом.
- `local_llm.py` (способ 2): llama.cpp (сборка Vulkan) как локальный сервер,
  модели Gemma 4 GGUF, пресет подбирается по ОЗУ/видеопамяти. Модель качается сразу с
  Hugging Face и его зеркала ModelScope (файлы одинаковые — размер и SHA-256 закреплены в
  пресете); не скачалась — можно скачать браузером и указать файл (`import_model`).
- `cloud.py` (способ 3): любой OpenAI-совместимый API; список моделей берётся
  у провайдера, `recommend()` ставит подходящие для перевода первыми.
- `llm.py`, `prompt.py`: общий клиент и промпт для нейросетей (JSON-ответ,
  короткие id, соседние реплики как контекст, деление пачки при сбое).
- `live_server.py`: HTTP-сервер для XUnity (Unity) — перевод на лету.

## Unity (`engines/unity/`)

Перевод работает в самой игре: BepInEx + XUnity.AutoTranslator
(`xunity.py`). Русификатор заранее готовит словарь
`BepInEx/Translation/ru/Text/_Russificator.txt`, а строки, которых в нём нет,
XUnity присылает на `live_server.py` (порт 47631).

Откуда берётся текст для словаря (`extract.py`, `text_assets.py`):
- компоненты текста сцен и префабов (UGUI Text, TextMeshPro, NGUI, TextMesh):
  typetree скриптов строится из сборок игры (TypeTreeGenerator), для IL2CPP —
  из `GameAssembly.dll` + `global-metadata.dat`;
- строковые поля скриптов (фразы, короткие названия в полях вроде `productName`);
- скрипты, чей typetree не сходится с данными, читаются по сырым байтам
  (строка Unity = int32 длина + UTF-8 + выравнивание 4);
- литералы кода (`#US` .NET-сборок или строки `global-metadata.dat`);
- текстовые ассеты и текстовые файлы `StreamingAssets` (json, csv/tsv, xml, txt, yaml,
  ink, yarn…): JSON, CSV/TSV (колонка английского), XML, Ink (`^текст`), Yarn («Имя:
  реплика»), простой текст — только то, что похоже на фразы; таблица локализации
  «идентификатор → текст» (`"LBL_CRYO_POD": "Cryo pod"`) берётся целиком, с короткими
  подписями (кроме титров и списков спонсоров — там имена людей). Таблицы других
  языков (ассеты «French», «Chinese Simplified», файлы `strings_fr.csv`, папки `de/`,
  бандлы Unity Localization `…(da-dk)…`) пропускаются, если рядом есть английская;
- подсказки клавиш «[E] to interact» — текст, а не метка журнала «[Info]»;
- строки, которые игра показала во время прошлых сеансов, а поиск не нашёл
  (`coverage.py`, см. ниже), входят в словарь следующей русификации;
- страницы встроенного браузера ZFBrowser (`zfbrowser.py`, пакет
  `Resources/browser_assets`, формат `zfbRes_v1`): переводятся прямо в
  пакете, только видимый текст, русские буквы — HTML-сущностями.

Плагин русификатора в игре (`resources/unity/RussificatorUnity.cs` →
`Russificator.Unity.dll`, BepInEx 5, Mono; все типы Unity/TMP — через отражение,
поэтому одна сборка работает на Unity 5–6):
- при старте игры читает `BepInEx/config/Russificator.cfg` и, если порт живого
  перевода свободен, запускает программу в режиме `--serve <игра> --pid <процесс>`
  и ждёт, пока она откроет порт, — не дольше 3 секунд, дальше в фоне: плагины старых
  Unity грузятся вместе с первой сценой (часто это уже главное меню), и долгое ожидание
  было бы зависшей игрой; программа закрывается вместе с игрой. Живой
  перевод поэтому работает при любом способе запуска игры;
- перехватывает `TMP_Text.SetText(string)` (XUnity его не видит) и направляет
  через свойство `text`;
- после перевода проверяет элемент TextMeshPro/UGUI: русский текст вылезает за
  рамку или рвёт слово (перенос посреди слова виден в `textInfo`), а английский
  помещался — включает автоподбор размера от исходного вниз до 60%; надпись,
  которая по-английски была в одну строку, а по-русски переносится (вторая строка
  наехала бы на соседние элементы), уменьшается ровно до одной строки (тоже не
  мельче 60%). Оригинал текста из сцены плагин берёт из компонента в момент,
  когда XUnity пишет туда перевод.

Полнота перевода (`coverage.py`). Всё, чего не было в словаре, XUnity отправляет живому
переводу и дописывает в `_AutoGeneratedTranslations.txt` — это и есть список пропусков
поиска. Перед откатом и повторной русификацией он сохраняется в проекте
(`live_found.json`, иначе откат удалял его вместе с BepInEx) и входит в следующий словарь —
значит, и в архив «для друзей». «Мои игры» → «Полнота перевода» (или
`russificator coverage <игра>`) разбирает игру тем же поиском, но запоминает все строки до
отбора, и раскладывает каждый пропуск: теперь находится заранее / есть в файлах, но
отброшена фильтром (с причиной и местом) / шаблон с подставленным значением / собрана из
кусочков / не найдена в файлах / имена из титров / переводить не нужно. Отчёт пишется в
папку проекта («Полнота перевода.txt»).

Надёжность живого перевода. XUnity отключает перевод после 5 ошибок подряд,
поэтому сервер открывает порт за доли секунды (переводчик готовится в фоне), а
запросы ждут готовности модели. Негодный перевод переводится по кускам, а если
и так нельзя — возвращается оригиналом, а не ошибкой. Для IL2CPP (плагина нет)
ярлык «Играть на русском» (`core/launcher.py` → `play.py`) поднимает сервер без
окна, запускает игру и закрывается вместе с ней (ждёт и перезапуск через Steam).

IMGUI (`GUI.Label`…) XUnity перехватывает, только если `il_scan.py` нашёл такие
вызовы в коде игры.

Текст, печатающийся по буквам: `GeneratePartialTranslations=True`, если
словарь небольшой (бюджет по сумме квадратов длин строк). Тогда XUnity
заранее строит перевод каждого начала строки — и подставляет его в любой текст,
совпавший с таким началом: буква «B» в сетке ввода имени становилась «Б». Поэтому в
словарь пишутся записи «как есть» для букв, цифр и 1–2 первых знаков каждой строки
(`short_guards`): точная запись важнее частичной. Если код игры дописывает буквы к
тексту, прочитанному из компонента (`label.text += c`), включается ещё
`TextGetterCompatibilityMode`: коду игры возвращается оригинал. Нужен ли он,
решает `il_scan.py`: он разбирает IL-код сборок игры и ищет шаблоны
«get_text → Concat → set_text» (нужен) и «text.Length → maxVisibleCharacters»
(вреден: игра обрезала бы более длинный русский текст).

Подписи, к которым код приклеивает текст (`"Pro Tip: " + tip`), берутся из
литералов кода и записываются в словарь как splitter-regex XUnity
(`sr:"^Pro Tip: ([\S\s]+)$"=Совет: $1`): подпись переводится один раз, а
вставка — по словарю или живым переводом.

TextMeshPro: XUnity перехватывает свойство `text` и `SetText(string, bool)`, но
не `SetText(string)`, которым пользуются игры на старом TMP. Плагин
`resources/unity/RussificatorTmpFix.dll` (исходник рядом, `.cs`) перенаправляет
`SetText(string)` в свойство `text`. Ставится для Mono-игр с BepInEx 5.

TextMesh и компоненты, которых XUnity не знает (`RussificatorUnity.cs`, Mono):
- у TextMesh нет переноса строк — игры переносят английский текст сами. Русский текст, пришедший
  одной строкой, разбивается по ширине самой длинной строки оригинала; текст, перенесённый игрой,
  ищется в словаре и без её переносов (`FitLines`, `Unwrap`);
- надпись, которую игра переставляет каждый кадр (кнопки «BUY POTION», мигающее «insert coin»),
  XUnity бросает как «спам» — плагин подставляет готовый перевод из словаря XUnity
  (`AutoTranslator.Default.TryTranslate`) сразу в сеттере; «+2 Vitality», «Level 7» — число
  отдельно, слово по словарю;
- текст сцены, заданный до установки перехватов, никто не «ставит» заново — раз в секунду включённые
  TextMesh с английским текстом получают перевод из словаря;
- ex2D (`exSpriteFont`) XUnity не видит вовсе: сеттер перехватывается, тексты сцены сканируются, чего
  нет в словаре — запрашивается у XUnity (живой перевод) и ставится, если игра не сменила текст;
- после перестройки текстуры динамического шрифта (`Font.textureRebuilt` — в неё добавляются русские
  буквы) все TextMesh с этим шрифтом, в том числе неактивные, строятся заново: иначе неактивный в этот
  момент пункт меню показывает мусор вместо букв.
Если перевод выключен (Alt+T), плагин ничего не подставляет; сбой любой части выключает только её.
Диагностика: файл `BepInEx/config/Russificator.debug` — первые 400 событий текста в журнал BepInEx.

Правила словаря, кроме шаблонов из кода: «число + слово» (`number_rules`: число остаётся, слово —
по словарю), «по абзацам» (`paragraph_rules`); пробелы и переводы строк в шаблонах совпадают с любыми
пробельными (`_flex_ws`) — игра переносит строки сама. Строки-форматы из полей скриптов и кода
(«{0} / {1} completed», «Level {0}») собираются, даже если «предложением» не выглядят.

Русский текст шире английского: для переведённых компонентов пишется
`_Russificator.resizer.txt` с `AutoResize(true, 60%, исходный размер)` по полному
пути объекта в сцене (так XUnity ищет правила). Шрифт не становится крупнее
исходного и уменьшается, только если текст не помещается.

Шрифты (`tmp_cyrillic.py` + `fonts/cyrillic.py`, `fonts/sfnt.py`). Без кириллицы
в шрифте Unity берёт русские буквы из системного Arial того же кегля, а он другого
роста — текст выходил в 1,5–2 раза крупнее и наезжал строками. Поэтому буквы
дописываются в сами шрифты игры по меркам каждого шрифта:
- `Font` с TTF/OTF внутри (UI Text, TextMesh, IMGUI, исходники динамических
  шрифтов TMP) — кириллица встраивается прямо в шрифт (`sfnt.py` читает glyf и CFF,
  собирает TrueType заново; CFF переводится в квадратичные контуры);
- атласы TextMeshPro (v1, v2 и обновлённые из v1 — у них старый список пуст) —
  мерки снимаются с глифов атласа, русские двойники латиницы ссылаются на её
  глифы, остальные рисуются в SDF с параметрами шрифта (Padding, GradientScale)
  кеглем атласа; если исходный TTF есть в игре — им самим. Атлас растёт при нехватке;
- растровые шрифты (`Font` с текстурой) — так же, у пиксельных без полутонов;
- шрифты ex2D (`exBitmapFont`: разметка BMFont + текстура) — так же; текстура при нехватке места растёт
  вниз, нормированные UV всех символов пересчитываются, общая текстура у нескольких шрифтов — одна.

Мерки (`cyrillic.measure`/`style_from_glyphs`): высота заглавных и строчных и их
подъём над базовой линией, средняя ширина латиницы, толщина вертикального и
горизонтального штриха (у строчных — по «l»), наклон, моноширинность, «капитель»
(строчные нарисованы как маленькие заглавные), пиксельная сетка. Буквы берутся из PT
Sans (обычного или полужирного — что ближе по весу), масштабируются по высоте и
ширине и утолщаются/утончаются сдвигом контура (как синтетический полужирный
FreeType). Пиксельные шрифты (`fonts/pixel_cyrillic.py`) собирают русские буквы из своей
же латиницы, клетка в клетку, как это делает шрифтовик: И — зеркальная N (если у N есть
диагональ), Я — зеркальная R, Ь — чаша P внизу, Г — перевёрнутая L, З — цифра 3; П, Ч, Ц,
Ш, Щ, Л, Д, У — из стоек и перекладины H (толщина — по самой частой строке H, срезы концов
сохраняются), Ж — из K, Ф и Ю — из O. Строчные — те же формы ростом строчных
(`fit_rows` убирает строки, не разрывая букву и не теряя просветов), б — из 6, ф — из o.
Так же — по картинкам латиницы атласа TextMeshPro. Буква пишется одним контуром по
границе клеток (россыпь квадратиков хинтинг Unity сдвигает по-разному), кратка Й и точки Ё
поднимаются над заглавной не выше, чем знаки собственных букв шрифта (Ë, É…); нет таких
букв — знак остаётся в высоте заглавной (строки меню стоят вплотную), Ё без места — как Е.
Шрифт, где латиница не «стойки и перекладина» (контурный, «строчками»), рисуется прежним
способом: PT Sans без сглаживания кеглем той же высоты; широкие буквы в узкой клетке
моноширинного шрифта сжимаются по столбцам. А, В, Е, К, М, Н, О, Р, С, Т, Х, а, е, о, р,
с, у, х и Ё (если «Ë» в шрифте настоящая, а не псевдографика DOS) берутся из самого
шрифта. Собранный шрифт проверяется FreeType: открывается, новые буквы рисуются,
латиница не изменилась; после записи файл ассетов перечитывается. Изменённые бандлы
Addressables получают нулевой CRC в каталоге (`addressables.py`), иначе Unity их не
загрузит.

## Ren'Py (`engines/renpy/`)

- `archive.py`: RPA-2.0/3.0/3.2, индекс читается безопасным unpickler'ом;
- `rpyc.py`: скомпилированные скрипты читаются без выполнения кода
  (заглушки классов Ren'Py), `rpy_parse.py`: исходники, по правилам лексера Ren'Py;
- кроме реплик, меню и `_()` извлекаются аргументы `renpy.notify`, `renpy.input`,
  `renpy.say`, `Text`, `Confirm`, `Notify` и свойства экранов (`tooltip`…);
- встраивание: `game/russificator_tl.json` + `zz_russificator.rpy`
  (`config.say_menu_text_filter`, `config.replace_text`), шрифты без
  кириллицы подменяются через `config.font_replacement_map` копиями с русскими
  буквами, дописанными по меркам шрифта (`game/russificator/<шрифт>-ru.ttf`);
  если шрифт дополнить нельзя — PT Sans;
- реплика, которая не помещается в окно диалога (высота меряется самим Ren'Py:
  `Text(...).size()`), получает `{size=-N}` ровно на нужную величину — только в
  режиме ADV и только если английский оригинал помещался.

## RPG Maker (`engines/rpgmaker/`)

- `layout.py`: перенос по ширине в пикселях (метрики PT Sans из `fonts/metrics.py`)
  с размерами окон каждой версии, поправкой на разрешение (MZ — `System.json`, MV —
  параметры плагинов) и шириной управляющих кодов;
- MV/MZ (`mv_mz.py`): блоки сообщений (101 + 401) переводятся целиком и заново
  переносятся по ширине окна (с портретом и без), выборы, прокрутка, база
  данных, `System.json`, названия карт, `$gameMessage.add` в скриптах (355/655),
  аргументы команд плагинов MZ (357) и параметры `js/plugins.js`
  (`plugin_text.py`: только «текстовые» имена параметров, JSON внутри строк
  раскрывается и собирается обратно). Плагин `resources/rpgmaker/Russificator.js`
  (подключается последним) переносит слово, которое не влезло в окно
  сообщения/прокрутки/справки, и уменьшает шрифт описаний и строк боя; проверен на
  моделях окон MV и MZ (`tests/js`). Шрифт: копия шрифта игры с русскими буквами
  по его меркам (`fonts/cyrillic.py`; не вышло — PT Sans): MV — `@font-face` с
  `unicode-range` для кириллицы, MZ — `mainFontFilename`;
- XP/VX/VX Ace (`old_marshal.py`, `ruby_marshal.py`): точный читатель/писатель
  Ruby Marshal 4.8, архивы RGSSAD v1/v3 (`rgssad.py`) распаковываются в `Data/`.
  Надписи в скриптах (`rgss_scripts.py`): константы `Vocab`, «текстовые»
  константы, `add_command`, `draw_text`, меню XP — замена литерала по месту с
  экранированием Ruby. Описания VX Ace разбиваются на две строки (или получают
  `\}` — меньший шрифт). Шрифт: шрифты из `Fonts/` дополняются кириллицей на
  месте; если их нет или дополнить нельзя — PT Sans в `Fonts/` + скрипт перед `Main`.

## Данные программы (`paths.py`)

Всё лежит в `RussificatorData` рядом с exe (из исходников — `userdata/`):
`models/` (машинный переводчик, GGUF), `tools/` (llama.cpp, BepInEx, XUnity),
`cache/` (память переводов), `covers/` (свои обложки «Моих игр»), `projects/`, `logs/`
(`russificator.log` и `live.log` — прошлый запуск остаётся в `*.prev.log`; `downloads.log` —
каждая попытка загрузки, дописывается; `play.log`), `settings.json`. Папку можно перенести в
настройках.

## Загрузки (`net.py`)

`net.download` качает большие файлы в несколько соединений кусками (Range) и с нескольких
зеркал одного файла сразу: медленное соединение уступает кусок быстрому источнику, сломавшийся
сервер (404, другая версия файла) просто не берётся. Обрыв или зависание (30 с без данных) —
повтор с паузой; загрузка сдаётся только после 5 минут без единого байта, и скачанное
сохраняется (`.part` + раскладка `.part.json`): «Скачать» ещё раз продолжает с того же места.
Готовый файл сверяется с SHA-256 (сервер сообщает её в `X-Linked-ETag`). Каждая попытка и её
причина — в `logs/downloads.log`.

## Русификатор «для друзей» (`core/package.py`, `installer/`)

Архив `<Игра> — русификатор.zip` = `Установить.exe` + `Прочти.txt` + лицензии +
`russificator-data/` (`package.json`, `translations.json`, `files/`, `patches/`).
Как ставить, решает движок (`EnginePlugin.export_plan` → `ExportPlan`):

- `files` (Ren'Py, Unity): копируются созданные русификатором файлы (из манифеста бэкапа,
  без кэшей BepInEx, логов и ярлыков); изменённые файлы игры — бинарными патчами
  `core/delta.py` (жадное совпадение блоков через `mmap.find`, проверка SHA-1 до и после);
  конфиги «для друзей» подменяются (Unity: без сервера программы, с надписью о программе);
- `reinject` (RPG Maker): у друга текст извлекается из его копии игры тем же кодом, перевод
  подставляется по адресу и тексту строки (`apply_translations`) и внедряется заново — так
  подходит к любой версии игры.

Установщик (`installer/app.py`, Tk, `installer.spec`) собирается без UnityPy/numpy: движки
Ren'Py и RPG Maker — чистый Python (XOR архивов RGSSAD без numpy — длинной арифметикой).
Всё пишется через `GameBackup`, поэтому удаляет и установщик, и программа («Откатить»).

`GameBackup.snapshot()` запоминает размер и время изменения файлов после русификации:
«Мои игры» видят, что обновление игры затёрло перевод, а откат не возвращает старые
файлы поверх обновлённых (`forget_updated`).

## Мои игры (`library.py`, `ui/games.py`)

Источники: Steam (`libraryfolders.vdf`, `appmanifest_*.acf`), GOG и Ubisoft (реестр), Epic
(манифесты `.item`), itch.io (папка приложений и `butler.db`), Game Pass (`XboxGames` на
дисках), список установленных программ Windows (только папки с игровым движком), свои папки
и проекты программы. Движок определяется быстро по характерным файлам. Список кэшируется в
`cache/library.json` и обновляется в фоне.

## Unity: шаблоны из кода (`xunity.template_rules`, `il_scan.concat_templates`)

Строки с плейсхолдерами `String.Format` («You have {0} coins») превращаются в правила-регулярки
XUnity: числа переносятся как есть (`r:`), текстовые вставки переводятся отдельно (`sr:`).
Склейки строк в Mono-коде находятся упрощённым вычислением стека IL (`String.Concat`, в том
числе с массивом) и становятся шаблонами «Day {0} of {1}». Ключи правил в файле XUnity
экранируются целиком (`xunity.encode`).

Плагин Unity — один исходник `RussificatorUnity.cs`: Mono (BepInEx 5) и с символом `IL2CPP`
(BepInEx 6, Il2CppInterop: объекты по указателю, текст через свойства, свой компонент для
Update/OnGUI). Сборка — `tools/build_unity_plugins.py`.

## Живой перевод (`overlay/`)

Процесс `Russificator.exe --overlay` (трей, автозапуск через `HKCU\...\Run`). Потоки не ждут
друг друга:

1. **Главный цикл** (`service._tick`, 15 кадров/с, пока что-то происходит; 7 — в покое):
   `detect.Decider` решает, игра ли окно переднего плана (списки, «Мои игры», GameConfigStore,
   файлы движка рядом с exe, полный экран; браузеры/мессенджеры/система — никогда); кадр снимается
   в постоянный буфер (`win32.Grabber`): с самого окна (`PrintWindow`, `PW_RENDERFULLCONTENT`), а
   если окно отдаёт однотонную заливку или кадр, не совпадающий с экраном (сверка раз в
   `CROSSCHECK` с, `_window_lies`: по яркости клеток и по деталям — на экране в клетке буквы, а с
   окна ровная заливка; так бывает, когда игру рисует OpenGL/Vulkan в дочернем окне, как у
   эмуляторов: с окна снимаются только меню и строка состояния), — с экрана (BitBlt). Окно перевода — многослойное с цветовым
   ключом: такое Windows 10 (2004+) умеет исключать из захвата (`WDA_EXCLUDEFROMCAPTURE`; окно с
   попиксельной альфой — нет, ошибка 8). Исключение включается, только пока кадр берётся с экрана
   (иначе перевода не было бы на скриншотах игрока). Полупрозрачное (плашки, края) смешивается
   с кадром под окном заранее (`render.to_colorkey`).
2. **`pipeline.Pipeline`** (в главном цикле, доли миллисекунды): кадр сравнивается с прошлым по
   клеткам 8×8. Распознавание запускают резкие изменения (буква, реплика), когда успокоились
   (`SETTLE`), или не реже `MAX_WAIT`, если не успокаиваются; плавная анимация фона — только раз в
   `WEAK_PERIOD` по накопленному изменению. Распознаётся полоса кадра, где сменилось; надписи,
   которые она задевает, — целиком. Места, где меняется, а нового текста нет (глитч, мигающий
   значок, логотип), проверяются всё реже (`_noise`). Каждая надпись (`LiveBlock`) несёт отпечаток
   (`pixels.Probe`): точки букв и цвет букв. Точки сменились и цвета букв не осталось дольше
   `GONE_HOLD` — надпись пропала, перевод убирается; точки сменились, а цвет на месте — надпись
   анимирована (`restless`): другое её прочтение принимается, только если повторится. Промах
   распознавания надпись не убирает. Непереводимое (имена, русский текст, названия, мусор) тоже
   запоминается (`skip`) — искажённое прочтение того же места не становится «новой» надписью.
   Показ — когда надпись подтверждена (окрестность замерла на `CONFIRM`, у допечатывающейся —
   `CONFIRM_TYPING`, или два прочтения совпали) и переведены все её предложения; пока текст
   допечатывается — виден прежний перевод (`prev`).
3. **Распознавание** (`service._ocr_loop`): `paddle.PaddleOcr` — PP-OCRv5 на onnxruntime.
   Устройство для детектора и для чтения строк выбирается замером на этом ПК (`_fastest`, с
   разными размерами входа, как в игре); сессии DirectML не удаляются до конца процесса (удаление
   одной ломает остальные). Детектор получает кадр, уменьшенный по размеру текста этой игры
   (`_det_budget`, ступенями); строка читается английской моделью, сомнительная (незнакомые слова,
   цифры в словах) — ещё и восточнославянской (так узнаётся русский текст: «Об игре», а не
   «06 urpe»); прочитанное кэшируется по отпечатку и по форме букв (`_ShapeCache`: фон под строкой
   может меняться). Запасной путь — Windows.Media.Ocr (pythonnet или PowerShell) с проверкой
   русским распознаванием и перечитыванием мелкого текста крупнее (`_refine`). Затем
   (`service._analyze`): куски одной строки склеиваются (`text.merge_rows`; кириллица посреди
   английской строки — английское слово с эффектом), строки — в абзацы (`text.group_lines`:
   разный цвет, черта рамки, пункты меню — разные надписи; размер шрифта сверяется по высоте
   «тела» букв, а не по рамке распознавания, которую раздувает значок «дальше»; полосы развёртки
   CRT-шейдера — фон, а не черты, `pixels.stripes`), и решается, переводить ли абзац целиком.
   Ошибки распознавания исправляются по словарю (`words.py`: частые слова модели переводчика +
   полный словарь SCOWL en_US, чтобы настоящие слова не «исправлялись»). Глубокий проход на замершем экране — полное разрешение (или `vision.variants` +
   `text.merge_deep` для Windows OCR).
4. **Перевод** (`service._translate_loop`): по предложениям (`text.sentences`), одним выбранным
   переводчиком — перевод показывается один раз и не подменяется; срочное (подтверждённые
   надписи) — вперёд, пропавшее с экрана — пропускается; общая память переводов и нечёткий кэш
   сессии (`TranslationCache`, похожий ключ — только с теми же числами). Фраза с другими числами
   (счётчик, таймер, «60 FPS») собирается из готового перевода (`text.NumberTemplates`), не
   занимая переводчик. Перевод без русских букв или совпавший с оригиналом — остаётся оригинал
   (`SKIP`). В `live.log` — что найдено на экране, что показано и что отброшено (раз на надпись).
5. **Показ**: `inline.render_item` стирает оригинал и пишет перевод в его стиле (цвет, обводка,
   жирность, пиксельность, наклон); размер шрифта — из `inline.StyleBook` (похожие надписи игры —
   один размер), не помещается — перенос вниз и вширь по свободному фону (`free_below`,
   `free_side`), и только потом меньше шрифт ступенями. Картинка надписи считается один раз.

Окно программы управляет процессом по HTTP на 127.0.0.1:47632 (`/status`, `/toggle`, `/reload`…).

Горячие клавиши (`RegisterHotKey`) регистрируются только пока на экране игра, поэтому в других
программах Alt+… не перехватываются; в играх, русифицированных файлами (есть `russificator_backup`
или XUnity), Alt+T остаётся игре. Обычное окно, не похожее на игру, запоминается как «кандидат» —
его можно включить из меню трея или вкладки. Если у полноэкранной игры с самого начала только
чёрные кадры (эксклюзивный полноэкранный режим без оптимизации Windows), служба подсказывает
переключить «окно без рамки». Кадр больше `OcrEngine.MaxImageDimension` уменьшается перед
распознаванием Windows.

Настройки пишут два процесса (окно и трей): `settings.save` сливает изменения — ключи, которые
этот процесс не менял с момента чтения, берутся из файла.
